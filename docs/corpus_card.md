# Corpus card — `artifacts/corpus`

**All motion in this corpus is simulated.** No real deck data is used anywhere in this project.
The corpus is generated by `dmf.sim` from `configs/sim/corpus.yaml` and is reproducible from that
config plus the seeding rule below; it is gitignored rather than committed.

Regenerate with:

```
python scripts/generate_corpus.py --config configs/sim/corpus.yaml --out artifacts/corpus --workers 24
```

## Contents

| | |
|---|---|
| Realizations | 2304 (frigate 1920, S175 384) |
| Rows | 13 824 000 (6000 per realization) |
| Record length | 600 s at 10 Hz, after discarding a 120 s spin-up from a 720 s synthesis |
| On disk | 1114 MB, snappy-compressed Parquet, one file per realization |
| Generation | 18 s wall clock at 24 workers (36-core WSL2 host) |

### Grid

| Axis | Values |
|---|---|
| Sea state | SS3 (Hs 1.0 m, Tp 7.5 s), SS4 (1.9, 8.8), SS5 (3.3, 9.7), SS6 (5.0, 12.4), all gamma = 3.3 |
| Heading | 180 (head), 135 (bow-quartering), 90 (beam), 45 deg (stern-quartering) |
| Speed | 0, 6, 12 kn |
| Vessel | `frigate` (124 m, primary), `s175` (175 m, held-out `unseen_vessel` hull) |
| Seeds per cell | 40 for `frigate`, 8 for `s175` |

0 deg following seas is deliberately absent — see `configs/sim/headings.yaml`.

`s175` carries fewer seeds because it is never trained on: it exists to be the `unseen_vessel`
test set, so it needs enough realizations for a stable test mean, not enough to fit on.

### Wave synthesis

299 components over `[0.2, 2.5] rad/s`, frequencies **jittered** uniformly within their bins,
random phases `U(0, 2*pi)`, all three DOFs driven from the same phase set. `dw = 0.007692 rad/s`,
so the period at which an un-jittered grid would repeat is `2*pi/dw = 816.8 s` — longer than the
600 s record, and jitter is on regardless. Gate 1 criterion 5 asserts the absence of an
autocorrelation spike at that period; see `docs/protocol.md` P1-D4 for why 299 rather than 300.

## Files and schema

```
artifacts/corpus/manifest.parquet                       one row per realization
artifacts/corpus/<vessel>/<ss>_h<heading>_u<speed>_s<seed>.parquet
```

One file per realization, so the Phase 2 realization-level split is a partition of a file list
and cannot put two windows from the same realization on opposite sides of a train/test boundary.

| Column | dtype | Units | Notes |
|---|---|---|---|
| `t` | float64 | s | **Absolute simulation time**: starts at 120.0, ends at 719.9. The only float64 column. |
| `roll`, `pitch` | float32 | deg | Positive to starboard / bow-up |
| `heave` | float32 | m | Positive up |
| `roll_rate`, `pitch_rate` | float32 | deg/s | Exact frequency-domain derivatives, not finite differences |
| `heave_rate` | float32 | m/s | |
| `heave_acc` | float32 | m/s^2 | Shared by both observation modes — it is the raw accelerometer channel |
| `roll_imu`, `pitch_imu` | float32 | deg | `ideal` attitude + 0.02 deg white noise + bias random walk |
| `heave_imu` | float32 | m | Rebuilt from `heave_acc`, see below |
| `roll_rate_imu`, `pitch_rate_imu` | float32 | deg/s | Gyro white noise |
| `heave_rate_imu` | float32 | m/s | Intermediate stage of the same reconstruction |
| `seed` | int32 | — | Ordinal within the grid cell, 0-39 (frigate) or 0-7 (S175) |
| `ss` | str | — | `SS3` .. `SS6` |
| `heading` | float32 | deg | |
| `speed` | float32 | kn | |
| `vessel` | str | — | `frigate` or `s175` |

Both observation modes live in the same file so the Phase 6 `ideal` vs `imu` ablation is a column
selection, not a corpus regeneration.

`manifest.parquet` adds `n_rows`, `fs_hz`, `duration_s`, `spinup_s`, `n_components`, `jitter`,
`encounter_monotonic`, `entropy` (the realization's derived seed entropy) and `path`.

## Seeding

Each realization's randomness is derived from its grid coordinates alone:

```
key     = "<vessel>|<sea_state>|<heading:.6f>|<speed:.6f>|<seed>"
entropy = SeedSequence([CORPUS_SEED_NAMESPACE, *blake2b(key, 16 bytes) as four uint32])
```

Two children are spawned from that sequence: one for the wave synthesis, one for the IMU
corruption. Consequences, all asserted in `tests/test_generate.py`:

- any single realization can be regenerated in isolation, without producing the rest of the corpus;
- the corpus bytes are **independent of `n_workers`** (generation at 1 and at 4 workers produces
  byte-identical Parquet files);
- adding a sea state or heading to the grid does not disturb the seeds of realizations already in
  it, because nothing is keyed by list position.

## Encounter-frequency regime coverage

`dw_e/dw = 1 - 2*w*U*cos(beta)/g` changes sign inside `[0.2, 2.5] rad/s` in exactly two cells:

| Heading | Speed | `w_crit` | Realizations |
|---|---|---|---|
| 45 deg | 6 kn | 2.247 rad/s | 192 (160 frigate + 32 S175) |
| 45 deg | 12 kn | 1.124 rad/s | 192 (160 frigate + 32 S175) |

**These cells are kept, not excluded** (`docs/protocol.md` P1-D1). Each wave component is
propagated with its own signed `w_e`, the transfer function is evaluated at `abs(w_e)`, and the
`encounter_monotonic` column of the manifest labels every affected realization. What is not valid
in those cells is the frequency-domain change of variable from a wave spectrum to an
encounter-frequency response spectrum; nothing in this project relies on it.

## Split policy

Splits are **by realization seed, never by time window**, and are built in Phase 2 by
`dmf.data.splits`. Two windows drawn from the same realization overlap in the wave field that
generated them, so placing one in train and one in test inflates every metric. Because the corpus
is one file per realization, a split is a partition of a *file list* — structurally incapable of
straddling a realization boundary.

The four evaluation regimes this corpus is built to support:

| Regime | Train | Test | Question |
|---|---|---|---|
| `id` | frigate, seeds 0-31 of every cell | frigate, seeds 32-39 of every cell | In-distribution accuracy |
| `unseen_seastate` | frigate SS3, SS4, SS5 | frigate SS6 | Extrapolation to rougher seas |
| `unseen_heading` | frigate 180, 135, 45 deg | frigate 90 deg (beam) | Worst-case roll condition |
| `unseen_vessel` | frigate (all cells) | s175 (all 384 realizations) | Transfer across hull dynamics |

The `seed` column is the small ordinal `0 .. seeds_per_cell-1`, not the generator entropy, so
`unseen_seastate`, `unseen_heading` and `unseen_vessel` hold out whole axes while `id` slices the
seed ordinal. The S175's 8 seeds/cell exist only to serve the last row; it is never trained on.

Two consequences to respect downstream:

- **Normalization statistics come from the training split only.** Computing channel means or scales
  over the whole corpus is a leak, and a subtle one — see `CLAUDE.md` non-negotiable 3.
- **`unseen_heading` holds out beam seas, which is where roll is largest and pitch is smallest.**
  Pitch there is carried entirely by the residual floor of P1-D2 (0.109 deg RMS for the frigate at
  SS5), so pitch skill in that regime is a statement about a small, deliberately-floored signal.

## Known limitations of this corpus

Carry these into the README:

1. **Linear seakeeping.** No nonlinear roll damping, parametric resonance, green water, or
   capsize physics. The frigate's 9.3 deg RMS beam-seas roll at SS6 (`Tp = 12.4 s` against
   `Tn_roll = 12 s`, i.e. near-synchronous) is where a linear model most overstates reality: a real
   hull's damping grows with roll amplitude and would cut that figure.
2. **Unidirectional, single-modal seas.** No directional spreading, no swell/wind-sea bimodality.
3. **Constant heading and speed within a realization.** No manoeuvring, no seaway-induced
   speed loss.
4. **Uncoupled modes.** Roll, pitch and heave share a phase set but not a mass matrix; there is no
   roll-yaw or pitch-heave coupling.
5. **Heading-factor residual floors** (`sqrt(sin^2 + 0.05^2)`, `sqrt(cos^2 + 0.05^2)`) are an
   engineering stand-in for hull asymmetry and short-crested residual excitation, not a derived
   quantity — `docs/protocol.md` P1-D2.
6. **The S175 is a parameter shift, not a hull-form computation.** Only the modal parameters and
   the two lengths/drafts differ, so `unseen_vessel` measures transfer across a parameter shift
   rather than across genuinely different RAOs.
7. **The `imu` heave channel leads the truth.** The causal double integration through two 0.03 Hz
   high-passes has near-unit magnitude in the wave band but a phase lead of about 48 deg at
   0.10 Hz (1.3 s), growing to 106 deg at 0.05 Hz. This is **not** leakage — the filter is causal
   and was verified so directly (wiping all future acceleration leaves earlier reconstructed heave
   bitwise unchanged), so the channel contains no future information. But it does make persistence
   on an `imu` input roughly twice as strong at a 1 s horizon, which would silently change the
   denominator of every skill score. The Phase 6 ablation must forecast the `imu` channels against
   `imu` targets. See `docs/protocol.md` P1-D6.
